# التثبيت بـ Docker Compose خطوة بخطوة

هذا أسهل طريق لتشغيل EA-Hub، ويناسب خادماً واحداً (جهازاً في الشركة، أو خادماً سحابياً، أو حتى حاسوبك للتجربة).

## ما الذي ستحصل عليه

ستعمل ست خدمات صغيرة معاً، ويديرها Docker تلقائياً:

| الخدمة | وظيفتها |
|---|---|
| `db` | قاعدة بيانات PostgreSQL 16. بياناتها محفوظة في مساحة دائمة لا تُحذف عند الإيقاف |
| `migrate` | تجهّز القاعدة وتنشئ حساب المدير الأول، ثم تتوقف (هذا طبيعي) |
| `app` | موقع EA-Hub نفسه |
| `caddy` | خادم الويب الأمامي. يصدر شهادة HTTPS مجانية تلقائياً عند استخدام اسم نطاق |
| `cron` | يشغّل المهام اليومية: النشرة البريدية والتنظيف وفهرسة البحث |
| `backup` | ينسخ القاعدة والملفات احتياطياً كل يوم إلى مجلد `backups/` |

## 1) جهّز الخادم

**الحد الأدنى:** معالج بنواتين، وذاكرة 2 جيجابايت (4 أفضل)، و10 جيجابايت مساحة.

### على Linux (Ubuntu/Debian)

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # ثم اخرج وادخل مرة أخرى
docker compose version          # يجب أن يظهر رقم إصدار v2
```

### على Windows أو macOS

ثبّت [Docker Desktop](https://www.docker.com/products/docker-desktop/) وشغّله، ثم انتظر حتى تظهر عبارة "Engine running".

## 2) نزّل المشروع

```bash
git clone https://github.com/E20E-Tools/ea-hub-selfhost.git
cd ea-hub-selfhost
```

إن لم يكن `git` مثبتاً، فنزّل المشروع ملفاً مضغوطاً (ZIP) من صفحة المستودع وفك ضغطه.

## 3) شغّل معالج الإعداد

```bash
./setup.sh          # Linux / macOS
```

```powershell
.\setup.ps1         # Windows (PowerShell)
```

إذا منع ويندوز تشغيل السكربت، فاستخدم:

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

أجب عن الأسئلة. اضغط Enter لقبول القيمة المقترحة بين القوسين. في النهاية يسألك المعالج: "تشغيل EA-Hub الآن؟"، فأجب بنعم. في أول مرة يستغرق التنزيل أو البناء من 3 إلى 10 دقائق.

> **إذا كان المستودع خاصاً:** صورة التطبيق على GHCR خاصة أيضاً. عندها إما أن تسجّل الدخول مرة واحدة بالأمر `docker login ghcr.io` (اسم المستخدم حسابك في GitHub، وكلمة المرور token فيه صلاحية `read:packages`)، أو تترك المعالج يبني الصورة على جهازك تلقائياً.

## 4) افتح الموقع

- الموقع: الرابط الذي عرضه المعالج، مثل `http://localhost` أو `https://hub.example.com`
- لوحة الإدارة: أضف `/admin` إلى الرابط، وادخل ببريد المدير وكلمة مروره

بعد أول دخول ناجح، يُستحسن أن تحذف قيمة `ADMIN_PASSWORD` من ملف `.env` وتبقي السطر فارغاً، وأن تغيّر كلمة المرور من لوحة الإدارة ← حسابي.

## الحصول على HTTPS باسم نطاق حقيقي

1. اشترِ اسم نطاق، أو استخدم نطاقاً فرعياً من نطاق شركتك، مثل `hub.company.com`.
2. في لوحة DNS أضف سجلاً من نوع **A** يشير إلى عنوان IP العام للخادم.
3. افتح المنفذين **80** و**443** في جدار الحماية:
   ```bash
   sudo ufw allow 80,443/tcp
   ```
4. شغّل `./setup.sh` من جديد، واكتب اسم النطاق عند السؤال الأول، ووافق على HTTPS.

يحصل Caddy على الشهادة ويجددها تلقائياً من Let's Encrypt دون أي تدخل منك.

### داخل شبكة الشركة فقط (بدون إنترنت)

- **أبسط خيار:** اكتب عنوان IP للخادم (مثل `192.168.1.10`). سيعمل الموقع على HTTP داخل الشبكة.
- **باسم داخلي مع HTTPS:** اكتب الاسم (مثل `hub.corp.local`) وارفض HTTPS التلقائي في المعالج. بعدها عدّل `.env` بحيث يصبح `SITE_ADDRESS=https://hub.corp.local` و`APP_URL=https://hub.corp.local`، وأزل علامة `#` من سطر `tls internal` في [`deploy/compose/Caddyfile`](../deploy/compose/Caddyfile). سيصدر Caddy شهادة داخلية، ويمكن لقسم تقنية المعلومات توزيع جذرها على الأجهزة.

## تغيير الإعدادات لاحقاً

لديك طريقتان:

- شغّل `./setup.sh` من جديد. يحتفظ المعالج بكلمات المرور والمفاتيح الحالية، ولا يغيّر إلا ما تعدّله.
- أو عدّل ملف `.env` مباشرة، ثم نفّذ:
  ```bash
  docker compose up -d
  ```

> ⚠️ **لا تغيّر أبداً** قيمتي `APP_ENCRYPTION_KEY` و`POSTGRES_PASSWORD` بعد أول تشغيل. تغيير الأول يُخرج جميع المستخدمين ويجعل المفاتيح المحفوظة غير قابلة للقراءة، وتغيير الثاني يمنع الاتصال بالقاعدة.

### تدوير الأسرار

```bash
selfhost/scripts/rotate-secrets.sh all        # أو: app-db | postgres | cron | metrics
```

يكتب السكربت قيماً عشوائية جديدة في `.env` (ويحفظ نسخة من الملف القديم باسم `.env.bak-<الوقت>`)، ويغيّر كلمات مرور القاعدة داخل PostgreSQL، ثم يعيد إنشاء الحاويات التي تستخدمها، دون أن يطبع أي قيمة. بعد تدوير `metrics` انسخ `METRICS_TOKEN` الجديد من `.env` إلى إعداد Prometheus. لا يُدوَّر `APP_ENCRYPTION_KEY` أبداً.

## الميزات الاختيارية

| الميزة | ما يلزم في `.env` |
|---|---|
| استعادة كلمة المرور والإشعارات والنشرة | `SMTP_HOST` و`SMTP_USER` و`SMTP_PASSWORD` و`SMTP_FROM`، أو `RESEND_API_KEY` |
| البحث الدلالي (بالمعنى) | `OPENAI_API_KEY` |
| المساعد الذكي بمزود خارجي | `GROQ_API_KEY`، أو من لوحة الإدارة ← الإعدادات ← المساعد الذكي |
| الحماية من البوتات | `TURNSTILE_SITE_KEY` و`TURNSTILE_SECRET_KEY` من Cloudflare |

كل ميزة تعمل تلقائياً عندما يكون مفتاحها موجوداً، وتتوقف بهدوء عندما يغيب. بعد أي تعديل نفّذ `docker compose up -d`.

## نسخة أصغر بدون نموذج البحث المحلي

تتضمن الصورة نموذج MiniLM (حوالي 120 ميجابايت) لبحث المساعد محلياً. لبناء صورة أصغر بدونه، اضبط `WITH_LOCAL_MODEL=0` في `.env` ثم نفّذ:

```bash
docker compose build
docker compose up -d
```
