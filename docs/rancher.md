# تشغيل EA-Hub عبر Rancher

يدير Rancher عناقيد Kubernetes، سواء كانت RKE2 أو K3s أو عناقيد مستوردة مثل AKS وEKS وGKE. يُثبَّت EA-Hub على أي عنقود يديره Rancher بالـ Helm chart نفسه، ويمكن تنفيذ كل الخطوات من واجهة Rancher في المتصفح.

> النسخة الإنجليزية: [en/deploy-rancher.md](en/deploy-rancher.md)

## الطريقة الأسرع: من كتالوج التطبيقات دون أي أوامر

1. افتح **Apps ← Repositories ← Create**.
   - اختر *Target: http(s) URL to an index generated by Helm*.
   - ضع في Index URL الرابط `https://e20e-tools.github.io/ea-hub-selfhost`، ثم Create.
2. افتح **Apps ← Charts ← EA-Hub ← Install**.
3. يعرض Rancher نموذج إعداد بأقسام: General وAccess وStorage وE-mail وOptional features. املأ عنوان الموقع وبريد المدير، وفعّل Ingress واكتب اسم النطاق إن أردت.
4. **كلمة مرور المدير:** إن تركتها فارغة تُولَّد تلقائياً. أمر قراءتها مكتوب في ملاحظات الإصدار (release notes) ضمن *Installed Apps*.

في Rancher 2.9 أو أحدث يمكن أيضاً اختيار *Target: OCI* مع الرابط `oci://ghcr.io/e20e-tools/charts`.

باقي الدليل يشرح التثبيت بالأوامر لمن يفضّلها.

## 1. المتطلبات

### العنقود الذي سيعمل عليه EA-Hub

| | الحد الأدنى | الموصى به |
|---|---|---|
| Kubernetes | **1.27 أو أحدث** (RKE2 أو K3s) | أحدث إصدار يدعمه Rancher لديك |
| سعة العُقد | 2 vCPU و4 GB ذاكرة متاحة | 4 vCPU و8 GB |
| التخزين | StorageClass افتراضي فيه **35 GB** متاحة (`local-path` في K3s، أو Longhorn، أو vSphere CSI، أو أقراص السحابة) | Longhorn أو CSI السحابة مع دعم اللقطات (snapshots) |
| متحكم Ingress | RKE2 يأتي مع **ingress-nginx** (الفئة `nginx`)، وK3s يأتي مع **Traefik** (الفئة `traefik`) | |
| HTTPS (اختياري) | cert-manager (من Rancher ← Apps ← Charts ← *cert-manager*) أو شهادتك الخاصة | |

### Rancher وجهازك

| المطلوب | التفاصيل |
|---|---|
| Rancher Manager | الإصدار 2.8 أو أحدث، بمستخدم له دور **Project Owner/Member** على العنقود المستهدف |
| أداة الأوامر | إما **Kubectl Shell** في المتصفح (فيه `kubectl` و`helm` جاهزين)، أو `kubectl` وHelm على جهازك مع ملف kubeconfig للعنقود |
| الوصول إلى الصورة | يستطيع العنقود سحب `ghcr.io/e20e-tools/ea-hub-selfhost` (الصورة عامة)، أو نسخة منها في سجلك |
| DNS | اسم نطاق، مثل `hub.example.com`، يشير إلى الـ ingress أو موزّع الحمل في العنقود |

## 2. افتح سطر أوامر على العنقود

**من المتصفح:** افتح Rancher ← **☰ ← Cluster Management** ← عنقودك ← **Explore** ← زر **>_ Kubectl Shell** أعلى اليمين. الأداتان `helm` و`kubectl` متاحتان فيه.

**من جهازك:** اختر Explore ← قائمة **⋮** ← **Download KubeConfig**، ثم:

```bash
export KUBECONFIG=~/Downloads/<cluster>.yaml
kubectl get nodes
```

## 3. أنشئ مشروعاً ومساحة أسماء (من واجهة Rancher)

افتح Explore ← **Cluster ← Projects/Namespaces** ← **Create Project** باسم `ea-hub`، ثم **Create Namespace** باسم `ea-hub` داخله.

يمكن أيضاً إنشاء المساحة من سطر الأوامر بـ `kubectl create namespace ea-hub`، ثم نقلها إلى المشروع من الواجهة.

## 4. صلاحية سحب الصورة (فقط إن كانت الصورة خاصة)

من واجهة Rancher: Explore ← **Storage ← Secrets ← Create ← Registry**، ثم املأ:
- **Namespace:** `ea-hub`
- **الاسم:** `ghcr-pull`
- **السجل:** `ghcr.io`
- **اسم المستخدم:** حسابك على GitHub
- **كلمة المرور:** رمز (token) بصلاحية `read:packages`

الأمر المكافئ:

```bash
kubectl -n ea-hub create secret docker-registry ghcr-pull \
  --docker-server=ghcr.io --docker-username=<github-user> --docker-password=<token>
```

## 5. احصل على الـ chart

في Kubectl Shell أو على جهازك:

```bash
git clone https://github.com/E20E-Tools/ea-hub-selfhost.git
cd ea-hub-selfhost
```

## 6. اكتب ملف الإعدادات

أنشئ الملف `my-values.yaml`:

```yaml
appUrl: https://hub.example.com
admin:
  email: admin@yourcompany.com
  password: choose-a-long-password
image:
  repository: ghcr.io/e20e-tools/ea-hub-selfhost
  tag: "<version>"
imagePullSecrets:
  - name: ghcr-pull                 # remove if not needed
ingress:
  enabled: true
  className: nginx                  # RKE2. Use traefik on K3s
  host: hub.example.com
  tls: true
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt   # if cert-manager is installed
# Longhorn example:
# storage: { storageClass: longhorn }
# postgres: { storage: { storageClass: longhorn } }
# backup: { storage: { storageClass: longhorn } }
```

## 7. التثبيت

```bash
helm upgrade --install ea-hub deploy/helm/ea-hub -n ea-hub -f my-values.yaml
kubectl -n ea-hub rollout status deploy/ea-hub --timeout=10m
```

في واجهة Rancher، تحت Explore ← **Apps ← Installed Apps**، يظهر الإصدار `ea-hub` مع حالته. وفي **Workloads** تظهر الـ Deployment باسم `ea-hub`، والـ StatefulSet باسم `ea-hub-postgres`، والـ CronJobs.

### طرق أخرى داخل Rancher

| الطريقة | متى تُستخدم | الخطوات |
|---|---|---|
| **Import YAML** | دون Helm إطلاقاً | شغّل `helm template ea-hub deploy/helm/ea-hub -n ea-hub -f my-values.yaml > ea-hub.yaml` على أي جهاز، ثم اختر في العنقود **⬆ Import YAML**، والصق الناتج، واختر مساحة الأسماء `ea-hub`. أو استخدم `deploy/kubernetes/ea-hub.yaml` مع الـ Secret الخاص بك، كما في [kubernetes.md](kubernetes.md) |
| **Continuous Delivery (Fleet أو GitOps)** | عدة عناقيد، والتغييرات تمر عبر Git | أضف GitRepo يشير إلى هذا المستودع بالمسار `deploy/helm/ea-hub`. احفظ إعداداتك في Kubernetes Secret، وأشر إليه بـ `helm.valuesFrom` داخل ملف `fleet.yaml` في مستودع الإعدادات الخاص بك |

## 8. DNS وHTTPS

1. **اعرف عنوان الـ ingress:** من Explore ← **Service Discovery ← Ingresses** ← `ea-hub`، أو بالأمر `kubectl -n ea-hub get ingress`.
2. **أنشئ سجل DNS:** سجل من نوع **A** للاسم `hub.example.com` يشير إلى ذلك العنوان، أو إلى عنوان موزّع الحمل.
3. **الشهادة:** مع cert-manager وClusterIssuer باسم `letsencrypt` تُصدر الشهادة تلقائياً. دون cert-manager، أنشئ TLS secret باسم `ea-hub-tls` من Explore ← Storage ← Secrets ← **TLS Certificate**.

## 10. التشغيل اليومي من Rancher

| المهمة | من واجهة Rancher | بالأوامر |
|---|---|---|
| السجلات | Workloads ← `ea-hub` ← ⋮ ← **View Logs** (اختر الحاوية `migrate` أو `app`) | `kubectl -n ea-hub logs deploy/ea-hub -f` |
| نسخة احتياطية الآن | Workloads ← CronJobs ← `ea-hub-backup` ← ⋮ ← **Run Now** | `kubectl -n ea-hub create job --from=cronjob/ea-hub-backup backup-now` |
| الترقية | Apps ← Installed Apps ← `ea-hub` ← **Upgrade** (إن ثبّتّه من الكتالوج) | `helm upgrade ea-hub deploy/helm/ea-hub -n ea-hub -f my-values.yaml --set image.tag=<new>` |
| المراقبة | ثبّت تطبيق **Monitoring**، فيظهر استهلاك المعالج والذاكرة تحت Workloads | |
| لقطات الأقراص | واجهة Longhorn ← Volumes ← `ea-hub-*` ← جدول اللقطات أو النسخ | |
| إزالة التثبيت مع الإبقاء على البيانات | Apps ← Installed Apps ← ⋮ ← Delete | `helm uninstall ea-hub -n ea-hub` |

## حل المشكلات

| العَرَض | الحل |
|---|---|
| الـ Ingress يعيد 404 | قيمة `ingress.className` خاطئة: استخدم `nginx` في RKE2 و`traefik` في K3s. تحقق بالأمر `kubectl get ingressclass` |
| القرص (PVC) في حالة `Pending` | لا يوجد StorageClass افتراضي. عيّنه في Rancher (Storage ← StorageClasses ← ⋮ ← Set as Default)، أو مرّر قيم `storageClass` |
| Pod Security Admission يمنع الحاويات | يعمل الـ chart دون صلاحيات root، مع seccomp `RuntimeDefault`، ويُسقط كل الصلاحيات، فيتوافق مع سياسة **restricted**. راجع أي قاعدة مخصصة في PSA أو Kyverno أو Gatekeeper |
| `ImagePullBackOff` | يجب أن يكون الـ pull secret في مساحة الأسماء `ea-hub`، ومذكوراً في `imagePullSecrets` |

باقي الخطوات مطابقة للدليل العام: [kubernetes.md](kubernetes.md) و[helm.md](helm.md).
